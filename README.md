# Лабораторна робота 2 — XML, XSD, XSL. Варіант 10 «Пиво»

Консольний Java-застосунок, який працює з XML-каталогом пива:

1. перевіряє документ `beer.xml` за схемою `beer.xsd`;
2. розбирає його трьома парсерами — **DOM**, **SAX** і **StAX** — у колекцію об'єктів `Beer`;
3. сортує колекцію за допомогою `Comparator`;
4. через **XSL** перетворює документ на XML зі зміненою структурою: плоский список
   `BeerItem` розбивається на підсписки за типом пива (`dark`, `lager`, `light`, `live`).

## Предметна область

Кореневий елемент — `Beer`, кожен сорт пива описує елемент `BeerItem`.

| Елемент / атрибут | Опис | Обмеження у схемі |
|-------------------|------|-------------------|
| `@id` | ідентифікатор | тип `xs:ID`, шаблон `beer-N`, обов'язковий |
| `Name` | назва пива | непорожній рядок до 100 символів |
| `Type` | тип пива | перелік: `dark`, `light`, `lager`, `live` |
| `Al` | алкогольне чи ні | `xs:boolean` |
| `Manufacturer` | фірма-виробник | непорожній рядок |
| `Ingredients/Ingredient` | інгредієнти | щонайменше два |
| `Chars/Strength` | кількість обертів, % | `(0; 20]`, лише для алкогольного |
| `Chars/Transparency` | прозорість, % | `[0; 100]` |
| `Chars/Filtered` | фільтроване чи ні | `xs:boolean` |
| `Chars/NutritionalValue` | харчова цінність, ккал | `[1; 500]` |
| `Chars/Bottling` | спосіб розливу | обов'язкові атрибути `volume` `(0; 50]` л та `material` (перелік) |

## Структура проєкту

```
src/main/resources
├── beer.xml        вихідний документ
├── beer.xsd        схема
├── beer.xsl        групування за типом
└── log4j2.xml      налаштування логера

src/main/java/com/brewery
├── Main                    точка входу
├── app                     сценарій роботи та параметри запуску
├── model                   Beer, Chars, Bottling, переліки
├── parser                  DOM / SAX / StAX парсери
├── validation              перевірка XML за XSD
├── transform               XSL-перетворення
├── comparator              компаратори для сортування
└── xml                     спільні фабрики JAXP, виняток
```

### Як уникнуто дублювання коду

* `BeerXmlTag` — єдине місце з назвами елементів та атрибутів.
* `BeerBuilder` — єдине місце, де текст із XML перетворюється на типізовані значення.
* `BeerEventAssembler` збирає об'єкти з подій «початок елемента / текст / кінець елемента»,
  тому SAX- і StAX-парсери лише передають йому події.
* `AbstractBeerParser` (шаблонний метод) відкриває файл, логує та обробляє помилки —
  конкретний парсер реалізує тільки саме читання.
* `XmlFactories` створює всі фабрики JAXP з однаковими безпечними налаштуваннями (захист від XXE).

## Запуск

Потрібна JDK 17+. Maven встановлювати не треба — у проєкті є Maven Wrapper.

```bash
./mvnw verify          # збірка, тести, звіт і перевірка покриття
./mvnw exec:java       # запуск із файлами за замовчуванням
```

У Windows замість `./mvnw` використовуйте `mvnw.cmd`.

Параметри запуску позиційні й необов'язкові: `[xml] [xsd] [xsl] [output] [sort]`, де `sort` —
`name`, `manufacturer`, `type`, `strength` або `nutritional_value`:

```bash
./mvnw exec:java -Dexec.args="src/main/resources/beer.xml src/main/resources/beer.xsd src/main/resources/beer.xsl output/beer-by-type.xml strength"
```

Результат перетворення записується в `output/beer-by-type.xml`.

## Логування

Використано Log4j 2 (`src/main/resources/log4j2.xml`): повідомлення рівня `INFO` і вище
виводяться в консоль, усе від `DEBUG` — у файл `logs/beer-xml.log` з ротацією за датою та розміром.
Для тестів є окрема конфігурація `log4j2-test.xml` (тільки консоль).

## Тести

Unit-тести написані на JUnit 5. Покриття рахує JaCoCo: звіт — `target/site/jacoco/index.html`,
збірка завершується помилкою, якщо покриття рядків нижче 95 %.
